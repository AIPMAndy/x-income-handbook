# 第 1 单实验计划｜14 天验证，不保证成交

> 目标：验证一个确定的客户问题能否带来有意愿、有资格的询盘。过程不依赖官方平台分成资格。

## 先填 8 个字段

- 受众：例如，有 3 年以上经验、求职 AI 产品岗位的中文用户。
- 狭窄问题：例如，项目案例无法证明 AI 能力。
- 承诺边界：45 分钟诊断，交付岗位匹配度清单和下轮行动，不保证录用。
- 可展示证据：匿名授权过的作品样例 / 自己原创的模拟案例（要标注模拟）。
- 有效询盘定义：用户主动咨询，清楚需要何种帮助，同意后续沟通。
- 接单入口：个人真实官网/预约页；不要私信群发。
- 报价：写清币种、交付、退款、支付方式和适用区域。
- 停止条件：两周内无法触达用户，或 10 次真实沟通仍找不到需求共性则调整。

## 第 1–3 天：准备

1. 用一句话描述“谁 / 什么问题 / 具体交付”。
2. 做一张样例结果图或一页匿名报告，去掉姓名、公司机密和联系方式。
3. 写清楚收费范围、交付周期和拒绝受理的情况。

## 第 4–7 天：发布

1. 发 3 条独立原创帖：问题判断、操作清单、具体场景；每条有独立事实。
2. 在自己了解的话题里自然参与高质量讨论，不群发推广。
3. 对主动问问题的人先了解情况；对方明确表达兴趣后再说明收费选项。

## 第 8–11 天：比较

- 记录：原创帖子链接、查看量、主动询盘、有资格的询盘、预约、支付、退款。
- 不要把“你好”“互关”当有效询盘。
- 与用户沟通前征得同意，不在公开仓库保存微信号、电话或简历。

## 第 12–14 天：决策

- 有成交：计算真实到账减实际成本和交付工时；不要急着放大流量。
- 有意愿无成交：检查价格、信任证明、交付范围和入口摩擦。
- 无有效询盘：先检查选题及客户匹配，不把发帖量加倍当万能解。

## 复盘模板

| 指标 | 本次值 | 证据/口径 |
|---|---|---|
| 原创帖子 |  | URL |
| 有效询盘 |  | 自愿咨询+具体问题 |
| 预约 |  | 合法记录 |
| 真实到账 |  | 扣退款，注意跨月 |
| 总耗时 |  | 内容+销售+交付 |
| 下一步 | 继续 / 调整 / 停止 | 理由 |

注意：这是方法训练，不代表用户或作者已有此收入结果。
